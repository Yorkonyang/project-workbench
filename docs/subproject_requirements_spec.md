## 1. 产品目标

在保持「项目→任务→待办」既有模型与项目负责制权限不变的前提下，以最低侵入成本支持"**项目下可建最多 3 级子项目、各页面按层级聚合展示、并可将相近项目合并到目标项目**"，让半导体靶材业务的多层研发/生产项目结构在系统内清晰可追溯、且重复项目可一键归并。

## 2. 用户故事

- **US-1 新建子项目**：作为项目负责人，我希望在任一项目卡片或详情页点「＋子项目」，填写比父项目更轻量的信息并自动继承 `parentProjectId`，以便把大项目拆成可独立推进的子项目。
- **US-2 查看层级（项目列表）**：作为项目成员，我希望在「项目管理」页看到主项目与其子项目以树形/缩进+折叠方式展开（可逐层展开到任务→待办），快速掌握层级结构与各自进度，且不丢失现有展开/折叠体验。
- **US-3 分层统计（仪表盘）**：作为管理者，我希望在仪表盘用「按层级汇总」开关切换——关=全局扁平统计（不重复计数），开=父项目的进度/任务数/未完成事项自动汇总其全部子孙。
- **US-4 跨层级检索（任务/时间线/文档）**：作为任务负责人，我希望在这些页按项目筛选时可选「含子项目」，并看到每条任务/里程碑/文档归属的"项目层级面包屑"，以便跨层级检索与确认归属。
- **US-5 项目合并**：作为项目负责人，当我发现某子项目与另一项目内容相近时，我希望在详情页发起「合并到…」，选目标项目并预览影响范围（任务/待办/文档/里程碑/风险/资源数量），确认后一键并入，源项目隐藏留痕（P2 可限时撤销），以消除重复、保持数据整洁。

## 4. 关键交互设计

### 4.1 新建子项目入口

- **项目卡片**（`ProjectCard` hover 操作区，仅 owner/admin 可见）：增加「＋子项目」图标按钮，点击打开 `ProjectForm` 预置 `parentProjectId`。
- **项目详情页 Header**（`ProjectDetailPage`，右上操作区）：「新建子项目」按钮，预置 `parentProjectId`，并预填负责人=父项目负责人、颜色继承父色、日期继承父区间。
- **`ProjectForm` 内**：渲染「隶属项目」下拉（复用现有 `parentOptions`，已含防环）；新建子项目时该值锁定为父项目且不可改。
- **深度兜底**：当父项目 `level >= MAX_DEPTH-1`（即达 孙 级，level=2）时，禁用「新建子项目」并 tooltip「已达最大层级（N 级）」。

### 4.2 层级展示方式建议（重点 · `ProjectsPage`）

采用**统一树列表**（非卡片网格），层级用「缩进 + 左侧连接线 + 层级徽标」表达：

```
▸ 主项目A (level0)  [12/20 任务]  [进度环]
   ├ 子项目A1 (level1)  [3/5 任务]
   │  ├ 任务a ...
   │  │   └ 待办 ...
   │  └ 任务b ...
   ├ 子项目A2 (level1)
   └ 直属任务c ...
```

- 行类型：主项目（level0）→ 子项目（level1+，缩进递增）→ 任务（再缩进）→ 待办（再缩进）。
- 主/子项目行左端：单个 chevron 控制「展开子节点」= 子项目行 + 直属任务行。
- 任务行左端：既有 chevron 控制待办展开（**保持现有体验不变**）。
- **与现有体验不冲突的做法**：把"项目行展开"语义从"仅显示任务"扩展为"显示（子项目 + 直属任务）"，用分组小标题「子项目 N 个」「直属任务 M 个」区隔，避免层级混淆。
- 顶部保留「全部项目」下拉（下沉复用 `collectSubtree`），选中父项目即聚焦其整棵子树；保留「已归档/待审批」切换（仍用卡片网格）。
- **分期建议**：先在主项目行下插入子项目行（只读缩进展示），再补子项目自身的任务/待办展开，降低重构风险。

### 4.3 各页面聚合展示方案（重点）

| 页面 | 现状 | 增量方案 |
|------|------|----------|
| **仪表盘** | 扁平统计（任务总数/未完成/里程碑/风险/成员），无层级 | 新增「按层级汇总」开关（默认关）。关=现状；开=父项目进度/任务数/未完成事项 = 自身 + 全部子孙聚合，`ProjectStats`/`ProgressComparison` 显示「自身 / 含子项目」双值。底层 `getSubtreeStats(rootId)` 递归统计子孙。 |

| **任务管理** | 单项目下拉筛选 | 项目下拉旁加「含子项目」勾选；勾选后纳入该项目的全部子孙任务；`TaskList`/`TaskKanban` 增加「项目层级」面包屑列（主项目/子项目A），使跨层级归属一目了然。 |

### 4.4 合并操作流程

1. **入口**：项目详情页「合并到…」（owner/admin，且项目非已归档）。
2. **选目标**：弹出项目树选择器，列出可选项（**排除自身及其全部子孙**防环；**排除已归档**）。
3. **预览影响**：自动统计将移动的 任务/待办/文档/里程碑/风险/资源 数量，及"源的子项目将改挂目标"列表；若源有子项目，提示「保留层级 / 拍平」两种策略（默认保留层级；若目标深度不足则自动拍平，见待确认 Q3）。
4. **冲突提示**：若有 `code` 重复将提示"将重排编号（如 `XM_001.02`）"；同名提示"允许重名"。
5. **确认**：高危确认弹窗（"合并后源项目将隐藏且默认不可撤销"）。
6. **执行**：后端批量将源关联数据 `projectId → 目标`；源子项目 `parentProjectId → 目标`（或拍平为目标的直属/上层）；源项目置 `mergedInto` 并隐藏（非删除，保留痕迹）。
7. **（P2）撤销**：合并日志支持限时回滚。

## 5. 待确认问题（需用户拍板）

1. **层级深度定义**：「最多向下三级（父→子→孙）」——即 `MAX_DEPTH=3`（根/父=0，子=1，孙=2，孙不可再建）。是否确认 level 计数为 0/1/2，且"孙"级项目不能再建子项目？
2. **子项目编号规则**：沿用全局 `XM_001` 顺序（无层级感），还是层级编号（如 `XM_001.01` / `XM_001.01.02`，对合并冲突与可读性更优）？**建议采用层级编号**。
3. **合并后子项目层级处理**：默认「保留层级」（挂到目标下）还是「拍平」（成为目标的直属/上层项目）？深度超限时是否允许拍平？
4. **合并冲突策略**：`code` 重复时自动重排层级编号 vs 保留并允许重复；同名是否允许重复、是否自动加后缀「（合并）」？
5. **合并是否可撤销**：本期是否必须支持撤销？若需，是否接受「24h 内可撤销 + 合并日志」方案（P2-1），还是合并即最终（仅强确认）？
6. **仪表盘默认口径**：层级汇总开关默认关（扁平、不重复计数）是否符合预期？还是希望默认开（父项目聚合子孙）？**建议默认关**。
7. **子项目是否独立归档与权限继承父 owner**：影响 P1-7/P2-3 范围（P0-6 已确保 owner 继承）。
